# Spec: Delete the changelog tooling the release workflow no longer uses

**Feature Branch**: `019-drop-changelog-tooling`
**Issue**: [#40](https://github.com/chrisgriffin/token-atlas/issues/40)

## Overview

Releases run through the shared Release PR workflow, which installs and configures its own changelog tooling. The repo still carries the old copies: `changelog-preset.config.mjs`, a `version:recommend` npm script, and three conventional-changelog dev dependencies. Nothing here runs them, and the preset's header already names a workflow that no longer uses it. This removes them.

## User scenarios

1. **Given** a contributor reading the repo root and `package.json`, **When** they look for how changelogs are made, **Then** they find no local preset or script that pretends to drive releases.

## Functional requirements

- **FR-001**: `changelog-preset.config.mjs` is deleted, with its `.vscodeignore` entry.
- **FR-002**: `package.json` carries no `version:recommend` script and no `conventional-changelog-cli`, `conventional-changelog-conventionalcommits` or `conventional-recommended-bump` dev dependency; `package-lock.json` is regenerated by `npm uninstall`.

## Success criteria

- [ ] The repo carries no changelog preset, no `version:recommend` script and no conventional-changelog dev dependency, and nothing else refers to them.
- [ ] **Runnable:** `test -e changelog-preset.config.mjs; echo $?` prints `1` (today `0`), and `grep -c "conventional-" package.json` prints `0` (today `4`).
- [ ] `npm run verify` exits 0.

## Out of scope

- `CHANGELOG.md` and its `.prettierignore` entry: the shared release workflow still generates it with conventional-changelog, so that comment stays true.
